## 2. 框架补全一：桌局生命周期（G-03）

### 2.1 状态机

```
DRAFT（配置中）──提交──► RUNNING ──终局判定──► ENDED ──生成复盘档──► ARCHIVED
                          │  ▲                    │
                     挂起│  │恢复                 │任意时刻（业主操作）
                          ▼  │                    ▼
                      SUSPENDED ────────────► ABANDONED（弃局）
```

| 状态 | 语义 |
| --- | --- |
| DRAFT | 向导页配置中；配置未冻结 |
| RUNNING | 对局进行中；LLM 回合调度、人类回合等待输入 |
| SUSPENDED | 挂起：暂停回合调度，保留全部状态；人类随时恢复 |
| ENDED | 达到终局阈值或 `max_rounds`；结算页展示 |
| ARCHIVED | 复盘档（含私密层与全部 thinking_text）已生成落盘 |
| ABANDONED | 业主主动弃局；记录保留但标记 `abandoned: true`，**不进任何评测统计** |

### 2.2 挂起与恢复的两条路径

| 场景 | 机制 |
| --- | --- |
| 浏览器关闭/刷新（宿主仍在运行） | WebSocket 断线；宿主**继续跑桌局**（LLM 回合照常），重连后按 `seq` 补发（G-02） |
| 宿主进程重启 | 宿主内存状态丢失 → 从 `stream.jsonl` **重放重建**（种子 + 决策序列 ⇒ 事件流重现，02 A-10 的直接应用）；桌局自动转 SUSPENDED 等待打开页面恢复 |

### 2.3 "再来一桌"

结束页按钮：同配置快照（`meta.json`）+ **新种子**开新桌；旧桌立即转 ARCHIVED。

### 2.4 对 04 的增补（G-04 / F-11）

对局主界面之外新增**桌局列表页**（宿主首页）：进行中 / 挂起 / 已结束三区，每桌提供 继续 / 弃局 / 复盘入口。登记为 04 决策 **F-11**，归入 W2 交付。

### 2.5 PVE 人类中途退出（G-08，业主裁决 2026-11-10）

**退出即弃局**：人类玩家中途退出 = 游戏结束——桌局立即转 ABANDONED（记录保留、标记 `abandoned: true`、不进评测统计）。"退出"以**显式操作**为准：对局界面提供"退出并结束本桌"按钮（二次确认）；浏览器意外关闭/刷新**不算**退出，走断线等待（§2.2），防止误操作毁局。不支持移除玩家后继续对局。

## 3. 框架补全二：数据落盘布局（G-07）

```
<数据根目录>/
├─ config/
│  └─ players/*.toml            # 03 §7 玩家配置（适配器+人格+Tuning）
├─ matches/<match_id>/
│  ├─ meta.json                 # 配置快照、模式、玩家名册、状态、种子
│  ├─ stream.jsonl              # 全量事件流（含评测层附件）★权威持久层
│  └─ log/
│     └─ match_<ts>_<mode>.log  # 04 §5 人读 LOG（边打边写）
└─ archives/<match_id>/
   ├─ replay.json               # 复盘档：种子 + 决策序列（含私密层）
   ├─ metrics.json              # 已算指标（§6.2）
   └─ report.md                 # 单桌报告（§6.5，含 AI 评述）
```

| 规则 | 内容 |
| --- | --- |
| 权威持久层 | `stream.jsonl` 是唯一权威：重放恢复、评测统计、复盘档生成全部从它派生；其余文件皆为投影 |
| `match_id` | `m_<开始时间戳>_<随机短码>` |
| 私密纪律 | 私密内容只存在于 `stream.jsonl` / `replay.json`（单机用户文件系统即边界，F-01）；LOG 与聊天流遵循各自视角纪律（04 §5） |
| 弃局 | `meta.json` 置 `abandoned: true`，评测统计读取时过滤 |

## 4. 框架补全三：集成契约细化（G-4）

### 4.1 WebSocket 事件类型（对 02 §5.1 的增补）

| 新增事件 | 载荷 | 流 | 说明 |
| --- | --- | --- | --- |
| `HandObserved` | player、dice、`leopard_flag`（围骰/全骰标注） | 仅观战流 | 纯 EVE 桌的**观战投影事件**（G-01）：不重用私密的 `HandShaken`，由引擎预渲染标注（04 F-09），前端零规则逻辑 |
| `ThinkingObserved` | player、thinking_text | 仅观战流 | 内心戏前导消息的数据事件（04 F-06：仅 EVE） |
| `MatchStateChanged` | match_id、状态（§2.1）、原因 | 双流 | 生命周期可见化 |

其余事件沿用 02 §5.1，按流裁剪：玩家流 = 公开层 + 本人 `HandShaken`；观战流 = 公开层 + `HandObserved` + `ThinkingObserved`。评测附件（03 §4 信封）随对应决策事件进入评测层通道，不进两条呈现流。

### 4.2 REST 端点最小集

| 端点 | 方法 | 用途 |
| --- | --- | --- |
| `/matches` | GET | 桌局列表（F-11） |
| `/matches` | POST | 开桌（DRAFT 配置提交 → 冻结 → RUNNING） |
| `/matches/{id}/state` | POST | 挂起 / 恢复 / 弃局 / 再来一桌 |
| `/matches/{id}/action` | POST | PVE 人类提交动作（02 §4 契约动作 JSON） |
| `/matches/{id}/files` | GET | LOG / 复盘档路径查询 |
| `/matches/{id}/stream` | WS | 玩家流或观战流（按桌型决定） |

### 4.3 PlayerView 字段定稿（02 §4 的字段级展开）

| 字段 | 说明 |
| --- | --- |
| `match_id` / `round_no` / `phase` | 桌局公共事实 |
| `my_hand` | 本人 5 骰（仅本人） |
| `bid_history` | 叫骰流水（动作 + 台词 + 署名，按桌级 `history_depth` 裁剪） |
| `wild_state` / `ones_called` | 2×2 状态 |
| `current_bid` | 当前最高叫（X, Y） |
| `legal_actions` | 唯一权威合法动作集（02 §3.1） |
| `scores` | 全员积分与阈值 |
| `chain_position` | 应牌链位置（被谁杀、倍数、可否反杀）——仅 RESPOND 阶段 |
| `seat` / `player_count` | 座位事实 |

### 4.4 重连协议定稿（G-02，裁决 04 N4-04）

**全量重放优先**：重连时客户端报 `last_seq`；差量 ≤ 阈值则增量补发，否则宿主从内存态全量重发（事件流已在内存与磁盘，重放成本可忽略）。不做快照机制——一种机制覆盖断线与宿主重启两条路径，实现面最小。

## 6. 评测设计（G-1，正式的 05）

### 6.1 管线与数据源

沿用 02 §8 三层管线：**确定性统计层**（唯一数字权威）→ **统计相关性层** → **AI 赛后评述层**（三禁）。数据源 = `stream.jsonl`（权威持久层，§3）+ 评测层"决策时刻私有事实"。

**决策时刻私有事实字段定稿（G-8）**：`turn_seq`、`actor`、`phase`、`seat`、`prev_bid`、`wild_state`、`ones_called`、`self_support`（决策者当时对被叫点数的自持支持数，按当时状态口径 R-37/R-38）、`legal_count`、`action`、`quote_len`、`correction_count`、`degraded`。

### 6.2 指标定义表（E-xx；全部默认过滤弃局与降级回合，可切换包含）

**竞技面**

| 编号 | 指标 | 定义（口径） |
| --- | --- | --- |
| E-01 | 场胜率 | 终局积分最小者的场次占比（并列各计一胜，分母按并列人数扩展） |
| E-02 | 终局积分分布 | 各模型终局积分的均值 / 中位 / 分布直方 |
| E-03 | 积分曲线 | 逐局累计得分折线（单桌）与跨桌平均曲线 |
| E-04 | 局负率 | 成为该局输家的局数 / 参加局数；附局均受罚码数 |

**决策面**

| 编号 | 指标 | 定义 |
| --- | --- | --- |
| E-05 | 诈唬频率 | `#{X − self_support ≥ 阈值(默认 2)} / #{叫骰}` |
| E-06 | 诈唬成功率 / 存活率 | 成功率 = 该诈唬叫骰为局内终叫且 `count ≥ X` 的占比；存活率 = 诈唬叫骰未被立即开杀的占比（威慑力） |
| E-07 | 挑战正确率 | 挑战后判定结果使挑战者免罚的占比；分 开杀 / 跳杀 / 连杀 统计 |
| E-08 | 斋系使用率 | 转斋 / 飞斋次数与占比；飞斋成功率；飞斋锁死局（01 §14.1 联动）出现率 |
| E-09 | 过 1 触发率 | "N 个 1"叫骰占比；触发后该局剩余叫骰中含 1 叫骰占比（掐癞子后续效应） |
| E-10 | 叫量水位 | 平均叫量 / `5N` |

**行为面**

| 编号 | 指标 | 定义 |
| --- | --- | --- |
| E-11 | 台词量 | 有台词决策占比、均长 |
| E-12 | 攻击性代理 | 挑衅词表命中率（词表可配置） |
| E-13 | 台词威慑相关 | `P(下家开杀 \| 上家台词含挑衅) − P(下家开杀 \| 无台词)`——只报相关不判因果（02 §8.1） |

**成本面（字段已预留，指标随评测工具实现）**

| 编号 | 指标 | 定义 |
| --- | --- | --- |
| E-14 | 成本与稳定性 | 每决策 tokens（入/出/思考）、延迟、调用次数；降级率 = 降级回合 / 总回合 |
| E-15 | 心口一致性（仅 EVE） | thinking 中声称的手牌意图与实际动作 / 实际手牌的偏差——抽取半自动，数字部分可算才算，其余归 AI 评述 |

### 6.3 批量调度器

| 项 | 设计 |
| --- | --- |

## 7. 端到端走查（G-5，完整性证明）

以 01 §13.1 例一（4 人 EVE、A 叫 6 个 4 → D 开杀 → C 围骰 → D 输 1 码）为脚本，验证四层无断链：

| # | 层 | 发生什么 |
| --- | --- | --- |
| 1 | 引擎 | `MatchStarted`（配置冻结、种子）→ `RoundStarted` → 摇骰 → 4 × `HandShaken`（私密）+ 纯 EVE 下 4 × `HandObserved`（G-01） |
| 2 | 宿主 | 信封 `{seq, type, payload}` 推观战流；LOG Writer 追加写 |
| 3 | 前端 | 聊天流"第 1 局开始"；骰盅卡更新（围骰/全骰标注已由引擎算好） |
| 4 | 引擎→适配器 | A 回合：引擎渲染 A 的 PlayerView（§4.3）→ deepseek 适配器 |
| 5 | 适配器 | ContextBuilder 装配（稳定前缀+动态局面）→ V4 调用 → 剥离 thinking → 自检"6 个 4" ∈ 合法集（起叫 ≥ 6 ✓）→ 附件信封 |
| 6 | 引擎 | 收 Decision；评测层记 `self_support` 等（G-8）；`BidMade` 出流；观战流附 `ThinkingObserved` |
| 7 | 宿主→前端 | 内心戏前导气泡（灰底"内心"）→ A 的叫骰气泡"6 个 4"；LOG 行 |
| 8 | 引擎 | B/C 依次决策（同路径）；D 决策为 `ChallengeMade`（开杀相邻上家 C，R-29 ✓） |
| 9 | 引擎 | 无应牌选项被触发（开杀不可反杀，R-34）→ `Revealed` 全开 → 内核计数：C 贡献 6（围骰 +1，R-39）→ `count(5)=12 ≥ 7` 成立 → D 输 |
| 10 | 引擎 | `RoundSettled`（D ×1 = 1 码）→ 积分更新 → 终局判定（未达 100）→ 下一局起叫者 = D（R-05） |
